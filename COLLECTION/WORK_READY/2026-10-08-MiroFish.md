## Why it is valuable
MiroFish is a complete social/multi-agent simulation system, not merely a prompt wrapper. Its workflow is:
1. seed material ingestion;
2. ontology/entity/relationship generation;
3. graph-backed memory construction;
4. persona/profile generation;
5. agent configuration;
6. OASIS multi-agent social simulation;
7. persistent/dynamic memory updates;
8. ReportAgent analysis with tools;
9. post-simulation agent/report interaction.

This gives Collection a reusable **scenario-rehearsal / swarm-simulation capability** that is materially different from a normal single-agent workflow.

## Exact implementation paths inspected
- `backend/app/services/ontology_generator.py` — LLM-driven ontology generation and validation.
- `backend/app/services/graph_builder.py` — graph construction, chunking, batch ingestion, graph lifecycle/reconciliation.
- `backend/app/services/oasis_profile_generator.py` — OASIS agent/profile generation.
- `backend/app/services/simulation_config_generator.py` — simulation configuration generation.
- `backend/app/services/simulation_runner.py` — background OASIS execution, process lifecycle, per-agent action logging, round state.
- `backend/app/services/zep_graph_memory_updater.py` / `zep_tools.py` — graph/memory update and retrieval/tool layer.
- `backend/app/services/report_agent.py` — post-simulation report generation, tool calls, logging and interaction.
- `backend/scripts/run_parallel_simulation.py` — parallel social simulation.
- `backend/scripts/run_twitter_simulation.py` and `run_reddit_simulation.py` — platform-specific simulation runners.
- `backend/tests/` — tests for LLM compatibility, ontology, simulation preparation, profile normalization and Zep integration.
- `Dockerfile` / `docker-compose.yml` — container deployment path.
